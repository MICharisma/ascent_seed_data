# Published seed schemas

The JSON Schema (Draft 2020-12) files in `v1/` describe YAML and JSON manifests:

- `manifest.schema.json`: the shared `micharisma-seeds/v1` envelope and nested groups, independent of any app's catalog.
- `asc.schema.json`: Ascent's entity types, local codes, permitted attributes and their allowed values, and reference names.
- `entity-sequences.schema.json`: the optional numeric sequence registry.
- `candidate-accounts.schema.json`: the worker subset for verified official Channels owned by existing people or candidacies. It references the generated Ascent schema, and adds required account fields and per-record source evidence. Owner existence and account collisions are checked by `tools/seed_contract.py accounts`; see [WORKERS.md](../WORKERS.md).

Contributors can validate a manifest against `v1/asc.schema.json` with any Draft 2020-12 validator. The schema does not require relationships on each record, because they can be inherited through scope; Ascent's importer still checks that references resolve and that definitions do not contradict each other.

`asc.contract.json` is generated by Ascent from its live importer: the accepted types, model columns, allowed values, nested lists (`ballot_lines`, `featured_candidacies`), and references. It is the input for `asc.schema.json`, not a manifest. Do not edit generated files by hand. The worker subset is maintained separately and is not generated by the exporter.

## Maintainer regeneration

From the Ascent repository, with the test database migrated to the intended schema:

```sh
RAILS_ENV=test bin/rails seed_library:contract
```

Then generate the schemas with `exe/export-seed-schemas` from the private `micharisma_seeders` repository. The exporter is on its `codex/published-seed-schemas` branch until that branch is merged; check it out separately so Ascent's pinned submodule is unchanged:

```sh
bundle install
bundle exec ruby exe/export-seed-schemas --catalog <ascent_seed_data>/schemas/asc.contract.json --output <ascent_seed_data>/schemas/v1 --base-url https://raw.githubusercontent.com/MICharisma/ascent_seed_data/main/schemas/v1
```

Add `--check` to confirm the published schemas are current, and `RAILS_ENV=test CHECK=1 bin/rails seed_library:contract` to confirm the contract matches the importer. Ascent's `spec/services/seeds/catalog_contract_spec.rb` fails when the contract is stale.
